Orchestra v0.3 Design Proposal
Adaptive Task & Agent Orchestration
Overview
This document describes the architectural evolution required for Orchestra to support adaptive software engineering workflows.

The current platform executes a static task graph generated by the planner. While this works well for simple and moderately complex projects, larger software systems inevitably require work to be discovered during implementation.

Version 0.3 introduces adaptive orchestration, allowing workflows to evolve while they are executing.

The core principle is simple:

Agents do not spawn agents. Agents discover work. The Scheduler creates tasks. The Dispatcher spawns execution workers.

This preserves Orchestra’s existing separation between the Control Plane and Execution Plane while enabling arbitrarily complex workflows.

Architectural Principles
Principle 1
Tasks are persistent.

Agents are temporary.

Tasks exist inside the Control Plane.

Agents exist only while executing work.

Principle 2
Only the Scheduler modifies workflows.

Agents never directly modify the DAG.

Agents request changes.

The Scheduler validates and applies them.

Principle 3
Agents never spawn agents.

They only emit work discovery events.

The Dispatcher decides how new work is executed.

Principle 4
Parent tasks suspend instead of completing.

A task resumes once all blocking conditions have been satisfied.

Benefits
Adaptive orchestration enables Orchestra to

solve problems not known during initial planning
decompose work incrementally
react to validation failures
incorporate human feedback
execute long-running workflows
scale safely across many concurrent workers
Most importantly, it changes Orchestra from a static workflow executor into a continuously evolving orchestration engine.

This capability becomes the primary architectural differentiator from traditional one-shot code generation and static multi-agent execution systems.

Success Criteria
Version 0.3 is complete when Orchestra can:

Discover new work during execution.
Mutate the workflow DAG safely at runtime.
Suspend and resume parent tasks transparently.
Spawn execution workers for newly created tasks.
Enforce inherited capability tokens for all spawned work.
Resume execution from checkpoints rather than restarting tasks.
Maintain a complete audit trail of every workflow mutation.
Execute arbitrarily deep adaptive workflows while preserving centralized orchestration and governance.
